# Эксплуатация и восстановление SABINE

Эта инструкция отделяет подтверждённый рабочий стенд от действий, которые ещё предстоит проверить. Скрипты из GitHub сами по себе не содержат сервер, базы и клиент и не разворачивают их на пустой Windows-ВМ.

## Перед любыми изменениями

- **Окно обслуживания:** дождитесь выхода игроков и проверьте подключения к TCP 7777. Не запускайте probe через аккаунт, которым сейчас играет пользователь: повторный логин может оборвать его сеанс.
- **Резервирование:** сохраните приватный snapshot диска и штатные SQL BACKUP всех используемых баз. Копирование открытых MDF/LDF не заменяет SQL backup.
- **Контроль состояния:** запишите SHA256 основных EXE, действующие INI/DSN, экспорт реестра и настройки задачи. Эти файлы могут содержать секреты и должны оставаться вне публичного Git.
- **Доступ:** сохраните проверенный SSH/RDP-путь администратора. SQL и внутренние игровые порты не открывайте всему интернету.

В публикации от 14 октября сервер не перезапускался и игровой сеанс не изменялся. Новый вариант установки supervisor и обезличенные шаблоны требуют отдельной проверки на восстановленном/остановленном стенде, не являются уже применёнными изменениями на SABINE.

## Управление работающей ВМ

Supervisor живёт в session 0 и выполняет PowerShell-файлы из `C:\l2work\cmd`. Результаты появляются в `C:\l2work\out`, исполненные команды переносятся в `done`; очередь имеет административные полномочия и не должна быть доступна обычным пользователям.

На своей машине задайте `L2_HOST`, `L2_USER` и `L2_PASS` безопасным способом, не фиксируя пароль в Git или истории команд. Ключ хоста должен быть предварительно сверён и занесён в known_hosts; `L2_TRUST_NEW_HOST_KEY=1` является явным ослаблением проверки и не должен быть постоянной настройкой.

```bash
printf '%s\n' '& C:\l2work\status_l2.ps1' | python scripts/l2cmd.py -
```

```powershell
# Содержимое команды для очереди supervisor: проверка и запуск
& C:\l2work\start_l2.ps1
& C:\l2work\status_l2.ps1
```

```powershell
# Только во время обслуживания; это принудительная остановка процессов
& C:\l2work\assert_no_players.ps1
& C:\l2work\stop_l2.ps1
```

Файл `assert_no_players.ps1` добавлен в репозиторий при публикации. На существующую ВМ он автоматически не копировался; при его отсутствии используйте проверку `Get-NetTCPConnection -State Established | Where-Object LocalPort -eq 7777` вручную.

Если `l2cmd.py` сообщил timeout, команда может всё ещё находиться в очереди или выполняться. Сначала проверьте `cmd`, `out`, `done` и лог supervisor, прежде чем повторять потенциально разрушительное действие.

## Подготовка восстановленного окружения

- **Windows и файлы:** восстановите свой совместимый нативный комплект в `C:\L2Server`, включая Script/map и сопутствующие ресурсы. Не считайте названия файлов доказательством их версии; сверяйте хеши.
- **SQL:** восстановите как минимум `lin2db`, `lin2world`, `lin2user`, `lin2comm`, `lin2log`, `lin2report`; убедитесь в доступности локального TCP 1433 и необходимых логинов/прав. Универсального SQL-установщика схем в этом репозитории нет.
- **Настройки:** сопоставьте INI с рабочими шаблонами. В `l2server.ini` и `L2NPC.ini` IP указывается без кавычек, `WorldId=1`; не переносите старый `WorldId=3` со стенда Imani.
- **Шаблоны:** заменяйте `__DB_PASSWORD__` только в приватной рабочей копии. Не импортируйте REG с этим значением буквально и не фиксируйте подставленный пароль в Git.
- **ODBC:** используйте 32-битные DSN для 32-битных демонов. Файловый DSN `linworld` у LogD относится к `lin2log`, несмотря на его имя.
- **Сеть:** публичные игровые порты 2106/7777, остальные межсерверные соединения локальные. Проверьте firewall Windows и security group провайдера отдельно.

Частичный `scripts/setup.ps1` запускается только при остановленных демонах и явно заданном `L2_DB_PASSWORD`. Он создаёт файловые DSN и часть ключей PROJECT_L2, исправляет Auth config и добавляет два игровых firewall-правила; не восстанавливает SQL, не устанавливает готовый packet fix, не удаляет старые широкие правила и не меняет глобальную DEP/антивирус.

Для LogD важен поиск относительных File DSN. На текущем стенде использовался следующий путь; соответствующий ключ задаётся из 64-битного PowerShell:

```powershell
$dsnDir = 'C:\Program Files (x86)\Common Files\ODBC\Data Sources'
New-Item -ItemType Directory $dsnDir -Force | Out-Null
$key = 'HKLM:\SOFTWARE\WOW6432Node\ODBC\ODBC.INI\ODBC File DSN'
New-Item $key -Force | Out-Null
New-ItemProperty $key -Name DefaultDSNDir -Value $dsnDir -PropertyType String -Force | Out-Null
# Копируйте только уже подготовленные локальные DSN с правильными реквизитами
Get-ChildItem C:\L2Server -Recurse -Filter *.dsn | Copy-Item -Destination $dsnDir -Force
```

## Supervisor на восстановленной ВМ

Установочный helper предназначен для нового остановленного стенда; он откажется заменять уже существующую задачу. Запустите `scripts/install_supervisor.ps1` из повышенного PowerShell, укажите Windows-учётную запись через Get-Credential и проверьте результат в Task Scheduler.

Скрипт копирует `scripts/supervisor/*.ps1` в `C:\l2work`, ограничивает ACL администраторами/SYSTEM и регистрирует задачу AtStartup. Задача не стартует автоматически в рамках установки; SQL-реквизиты нужно подготовить отдельно.

В `C:\l2work\local.ps1` можно локально задать `$DBUSER` и `$DBPWD`, либо передать пароль через окружение задачи `L2_DB_PASSWORD`. Такой файл не хранится в Git, должен иметь ограниченные ACL и не должен попадать в транскрипты; произвольные не-администраторские service accounts требуют отдельной настройки ACL и ещё не проверены.

После ручной проверки SQL, DSN и настроек можно запустить задачу и через её очередь вызвать `start_l2.ps1`. Файл `C:\l2work\autostart.enabled` включает стартовую процедуру после загрузки; отдельный полный reboot-тест остаётся обязательным.

## Восстановление AuthD и мира

Нужен `L2AuthD483.exe` с хешем из [манифеста](artifacts.json). `switch_auth_c2.ps1` резервирует прежний AuthD и выполняет переключение через supervisor; он останавливает также мир/NPC и должен использоваться только при отсутствии игроков.

Таблица `lin2db.dbo.server` для текущего стенда должна содержать Bartz с `id=1`, `ip=176.53.225.183`, `inner_ip=127.0.0.1`, `port=7777`. Скрипт восстановления строки server намеренно не автоматизирован: перед SQL-записью нужно сверить схему, существующие строки и адрес нового стенда, не удаляя чужие миры.

`repair_world_registration.ps1` относится к подтверждённой схеме `worldstatus(idx,server,status)` и добавляет строку только при её отсутствии. Не устанавливайте status=1 вручную как «доказательство работы»: этот статус должен выставить AuthD после регистрации L2Server.

## Базовое исправление пакетов

```bash
python scripts/build_c2_packetfix.py \
  --source /private/L2Server483.exe \
  --output /private/L2Server_C2_485_packetfix.exe
```

Передавайте оригинал с точным входным SHA256 из [манифеста](artifacts.json). Генератор изменяет протокол 481→485, добавляет секцию `.c2fix`, проверяет исходные инструкции и эмулирует изменения пакетов до сохранения EXE.

Затем приватно загрузите результат в `C:\l2work\L2Server_C2_485_packetfix.exe` и выполните `deploy_c2_packetfix.ps1` через supervisor. Скрипт проверяет исходный/новый хеш, отказывается заменять неизвестный бинарник или мир с активным игроком, резервирует предыдущий файл и перезапускает World/NPC.

Если подтверждённая версия уже установлена, deployment ничего не меняет и не перезапускает. Базовый SHA256 должен быть `46BDA8BEEE36F99B25D8EA5EFB315323A92CE1A0A134F06CB4C9B1C38027C1F1`; опцию `--npc-extension` не используйте для восстановления этой конфигурации.

Резервные пути текущего стенда описаны в [журнале](STATUS.md). Откат бинарника выполняйте только после выхода игроков и остановки World/NPC; убедитесь, что откатываемая версия соответствует нужному клиенту, иначе прежний сбой загрузки может вернуться.

## Клиентский комплект

Полный клиент и noGG-overlay хранятся приватно. Для нового адреса можно изменить только INI:

```bash
python scripts/build_sabine_client.py \
  --source-overlay /private/system_C2_485_noGG_Bartz.zip \
  --host 176.53.225.183 \
  --output /private/system_C2_485_SABINE.zip
```

Builder проверяет, что изменён ровно `system/l2.ini`, выполняет обратную расшифровку и сверяет CRC/ZIP. Он не создаёт noGG-патч и не проверяет безопасность сторонних DLL.

Перед заменой сохраните прежнюю папку system, закройте игру, распакуйте подготовленный комплект и запускайте `system\l2.exe`. Реквизиты аккаунта передаются отдельно; пароль в публичную инструкцию не включён.

## Приёмка после восстановления

- **Процессы и порты:** пять демонов, session 0, слушатели 2106/7777, NPC связан с игровым портом 2002.
- **Авторизация:** реальный клиент проходит Agree, видит Bartz online, переходит к персонажам.
- **Мир:** Start завершает загрузку, доступны движение и взаимодействие.
- **Данные:** проверены безопасные игровые действия, выход/повторный вход и сохранение прогресса.
- **Холодный старт:** выполнена плановая перезагрузка, проверены SQL, supervisor и мир.
- **Резервная копия:** восстановление snapshot/SQL backup проверено на отдельной ВМ.

Последние три пункта и полноценная игровая механика на SABINE ещё не подтверждены. Не называйте стенд production-ready на основании одного успешного входа.
