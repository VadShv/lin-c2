# Диагностика C2 485

Проверяйте шаг, на котором возникает проблема, а не только факт прослушивания порта. Сетевой smoke test с другим форматом списка серверов может пройти, хотя настоящий клиент всё ещё получает ошибку.

## Access failed после Agree

- **Настоящий запрос:** клиент C2 485 отправляет RequestServerList формата `4`; прежний AuthD311 отвечал `05 06`. Успех probe с форматом `0` не доказывает исправления этого шага.
- **Рабочий AuthD:** используйте точный `L2AuthD483.exe` из манифеста. При переключении не менялись SQL-привилегии или клиентский ZIP.
- **Конфигурация:** `serverExPort=2106`, реклама мира соответствует адресу, `SupportReconnect=true` согласован с `reconnectauth=1`.
- **Мир:** Bartz должен зарегистрироваться и быть online в worldstatus. Не подменяйте проверку подключений ручной записью status=1.

Контролируемая проверка `python scripts/probe_c2.py --agreement` требует отдельного диагностического аккаунта, `L2_TEST_USER`, `L2_TEST_PASS` и явного `L2_ALLOW_LOGIN_PROBE=1`. Она отменяет собственный логин после списка миров, но всё равно может оборвать уже активный сеанс того же аккаунта.

## Заставка Lineage после выбора персонажа и Start

На SABINE проблема оказалась в несовместимых форматах пакетов, а не в отсутствии персонажа. Замена только номера протокола 481→485 позволяла пройти ранние этапы, но не завершала вход в мир.

- **CharSelected 0x15:** вставлена нулевая длина blob перед временем мира, само время сохранено, после него добавлены три нулевых DWORD. На исследованном персонаже 243→259 байт.
- **UserInfo 0x04:** добавлены 47 нулевых байт дополнительных полей, 393→440 байт на том же образце.
- **Проверка:** `build_c2_packetfix.py` использует guarded hook, отдельную PE-секцию и x86-эмуляцию; валидатор читает форматы именно установленного Engine.dll.
- **Подтверждение:** после базового исправления пользователь сообщил об успешной загрузке мира. Дополнительный NPC-tail не был установлен.

```bash
python scripts/validate_c2_world_packets.py /private/packetfix-dump \
  --overlay /private/system_C2_485_SABINE_176.53.225.183.zip
```

Валидатор привязан к адресам строк форматов исследованного Engine.dll. Для другого клиентского бинарника его нужно адаптировать, а не считать результат универсальной проверкой всех C2-клиентов.

## ODBC и окна подключения

- **LogD:** относительный File DSN `linworld` должен находиться через 32-битный `DefaultDSNDir`; имя DSN не означает базу lin2world, на этом стенде используется lin2log.
- **AuthD:** окно `L2 ODBC Connection Info` использует `L2Conn`. Runtime-строка подключения может сохраняться самим AuthD в реестр и не публикуется.
- **Оконная станция:** на исследованном стенде PsExec/session 1 давал SQL_ERROR и повторяющиеся окна. Запуск через supervisor/session 0 решил этот конкретный случай.
- **Разрядность:** используйте 32-битный ODBC для демонов и 64-битный PowerShell для прямой записи WOW6432Node, чтобы не попасть в неожиданную перенаправленную ветку.

Повторно возникающее окно после ввода реквизитов может означать не ошибку автоматики окна, а неработающий DSN/SQL. Проверяйте соединение, имя базы, драйвер и права в том же контексте запуска.

## Мир не подключается к CacheD

Парсер исследованного `l2server.ini` не снимал кавычки с IP. Используйте `address=127.0.0.1`, а не `address="127.0.0.1"` в L2Server и NPC; проверяйте порт CacheD 2006 для мира и 2008 для NPC.

Согласуйте WorldId во всех актуальных конфигурациях с id мира. Архивное значение 3 на Imani не относится к текущему Bartz с id=1.

## Захват и расшифровка трафика

Захваты приватные: они могут содержать игровые идентификаторы, содержимое пакетов и данные авторизации. Не включайте их в GitHub и не публикуйте полный вывод анализатора без проверки.

`start_game_capture.ps1` добавляет фильтр TCP7777 и запускает ограниченный circular ETL размером 16 МБ; заранее просмотрите существующие PktMon-фильтры. После воспроизведения обязательно выполните `pktmon stop` и удалите добавленный фильтр после проверки его имени.

На этом стенде стандартное преобразование отдельных circular ETL возвращало пустой результат, хотя сырые буферы содержали Ethernet-кадры. Для этого случая сохранён эвристический recovery:

```bash
python scripts/extract_pktmon_raw.py /private/game.etl /private/game.pcap \
  --mac 02:00:00:00:00:01
python scripts/analyze_game_capture.py /private/game.pcap
```

В примере MAC фиктивный; используйте фактический MAC нужного интерфейса. Recovery не является универсальным ETL-парсером, не гарантирует полноту/хронологию и требует проверки пропусков TCP; анализатор рассчитан на потоки с начальным обменом ключом.

## Корректность диагностического протокола

- **Auth checksum:** XOR находится в предпоследнем DWORD (`-8`), последний DWORD зарезервирован. Включение хвоста в общий XOR давало ложные предупреждения.
- **GameCrypt:** длина тела добавляется к младшему DWORD ключа на смещении `0`, а не к старшему на смещении `4`.
- **Login probe:** по умолчанию реальный список формата `4`; формат `0` нужен только для изучения старого сервера.
- **Безопасность сеанса:** не выполняйте диагностический вход общим аккаунтом, пока пользователь играет. Offline-тесты запускаются без доступа к ВМ.
